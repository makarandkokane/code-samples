Binary search tree: requirements

What the tree demo has to prove, and the shape the proof depends on.

Requirements Design Tests Code

The program

BT-R1Plain C++17 and nothing else

  • C++17 and the standard library only, with no frameworks and nothing to install.
  • One class per file, so each tree and each walk can be read on its own.

Design BT-D1 Tests BT-T6

BT-R2The tree is always on screen

  • After every change the tree draws itself sideways, with the value count and the height under it.
  • An empty tree says so instead of printing nothing.

Design BT-D1 BT-D5 Tests BT-T1

BT-R3Wrong input is answered, not crashed

  • Duplicates are refused with a message, junk input is named, and the empty tree turns every operation away politely.
  • The threaded walks refuse to run before the threaded tree is built, and say which menu item builds it.

Design BT-D5 Tests BT-T5

The proof

BT-R4A search that shows its work

  • Every search prints the path it walked and the number of steps it took.
  • Each result is followed by the height, because no search can take more steps than that: the whole O(log N) claim in one line.

Design BT-D1 Tests BT-T2

BT-R5The worst case, then the cure

  • Sorted input must produce the degenerate tree, a stick as tall as it has values, and the demo loads that case on purpose.
  • Balancing rebuilds the same values into the flattest possible shape, and the same search must collapse from fifteen steps to four.

Design BT-D3 Tests BT-T2

The walks

BT-R6Three orders, two styles each

  • Preorder, inorder and postorder, each available both as the textbook recursion and as an explicit-stack rewrite.
  • The program compares the two sequences itself and says whether they agree.
  • Inorder on a search tree comes out sorted, and the balance operation depends on it.

Design BT-D2 Tests BT-T3

The threaded tree

BT-R7A threaded tree, kept apart

  • A right-threaded search tree in its own two files, with its own node struct and no dependence on the main tree.
  • Its inorder walk uses no recursion and no stack: every step is one pointer hop.
  • The threads can be listed, one line per spent null pointer.
