Requirements Design Tests Code

Behaviour

OM-T1An edit reaches the other two views

  • Type a new value into the table and press Enter.
  • Pass: the matching bar changes height and the summary total changes by the same amount.

Requirements OM-R1 OM-R2 OM-R4 Design OM-D1 OM-D6

OM-T2A new row appears in all three views

  • Add a row through the window.
  • Pass: table row, chart bar and summary count all go up by one.

Requirements OM-R5 Design OM-D1 OM-D2

OM-T3A removed row disappears from all three

  • Remove a row through the window.
  • Pass: the bar goes with it and the summary count drops by one.

Requirements OM-R5 Design OM-D1

OM-T4The views agree on the numbers

  • Read the tallest bar, then read the largest value in the summary line.
  • Pass: both name the same item, and the table shows that item with that value.

Requirements OM-R1 OM-R2 Design OM-D3 OM-D4

OM-T5A destroyed model is visible, not fatal

  • Destroy the model while the window is open.
  • Pass: chart and summary both say the subject is gone, and the app keeps running.
  • Fail: a blank chart that reads like an empty model, or a crash.

Requirements OM-R6 Design OM-D2 OM-D3 OM-D8

Static check

OM-T6No view mentions another view

  • Search BarChartWidget for SummaryPanel, and SummaryPanel for BarChartWidget.
  • Pass: no hits either way. A hit means the pattern has quietly broken.
  • BarChartWidget's header does name QTableView, in a comment explaining what it observes alongside. Prose, not a reference.

Automation

OM-T7The screenshot flag works unattended

  • Run observer-mvc --screenshot shot.png.
  • Pass: a PNG of the window is written and the process exits by itself.
