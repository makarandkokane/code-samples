The parts

OM-D1ItemModel is the subject

  • A QAbstractTableModel with two columns, a name and a value.
  • It emits dataChanged, rowsInserted, rowsRemoved and modelReset as the data changes.
  • Nothing else in the program stores item data.

Requirements OM-R1 OM-R4 OM-R5 Tests OM-T1 OM-T2 OM-T3 Code ItemModel.h

OM-D2One signal contract for every observer

  • Each hand-written view connects to the same five signals, destroyed included.
  • A view repaints or recomputes from the model on any of them, rather than tracking what changed.
  • That keeps a new view cheap to add: connect five signals and read the model.

OM-D3BarChartWidget, a view that is not a table

  • An ordinary widget with a custom paintEvent, drawing one bar per row.
  • It holds a plain model pointer and clears it when the model is destroyed.

Requirements OM-R2 OM-R6 Tests OM-T4 OM-T5 Code BarChartWidget.cpp

OM-D4SummaryPanel, the cheapest view of all

  • Recomputes count, total and largest item on every signal.
  • Proves the point that a view is anything that listens, not just what looks like a grid.

Requirements OM-R2 Tests OM-T4 Code SummaryPanel.cpp

OM-D5MainWindow is the only mediator

  • The one class that knows the model and all three views.
  • It does the wiring, so no view ever needs a neighbour's name.

OM-D6ValueDelegate keeps the value column typable

  • An item delegate that tidies the stock editor the base class already gives the column.
  • It takes away the spin box arrows, which crowd a column this narrow, and widens the range past the default of 99.

OM-D7Screenshot mode lives in main

  • --screenshot <file> grabs the window, writes the PNG and exits.
  • No test harness and no extra dependency: the app is its own screenshot tool.

The decisions

OM-D8Decision: a plain pointer, not a guarded one

  • A self-nulling smart pointer would have stopped the crash, and hidden the lesson.
  • It turns "the subject is gone" into "the subject is empty", and telling those apart is the exercise.
  • Qt makes the same call: its own item views keep a plain model pointer and observe destruction.

Requirements OM-R6 Tests OM-T5 Code BarChartWidget.cpp

OM-D9Decision: no view-to-view shortcuts

  • The chart could have listened to the table and saved a little wiring.
  • It would also have made the table load-bearing, and the pattern would stop being observable.
